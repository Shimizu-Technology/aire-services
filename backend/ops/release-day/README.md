## Why the existing paths differ

* **Payroll manual Lock for a published October 1–15:** `ManualCalendarFinalizer` chooses the actual database-clock lock instant. `BatchBuilder#settlement_seed_entries` uses the revision ledger for nominal work plus cases targeted to that calendar. It does not bulk-seed August/September history, though related previously represented work in the same overtime week can produce correction rows. October 1–15 itself is nominal work and would be payable without reconciliation. It is already paid by #94: do not Lock/import/pay it again.
* **Scheduled October 16–31, November 7 at 17:00 Guam:** `ScheduledCutoffFinalizer` freezes the published cutoff revision. Historical work enters through targeted cases and overtime context, not the arbitrary-range historical query. Missing legacy batch representation therefore does not by itself bulk-import August/September, but also does not prove safety. The new history gate blocks this path until eligible pre-rollout work has a recorded baseline, allocation or evidence hold. Genuine later changes to manual snapshots require explicit case routing.
* **Admin Finalize this cutoff:** without a calendar, `BatchBuilder` seeds nominal work, historical entries updated after the latest regular batch cutoff, prior changes, carryovers and manual-allocation changes. This was the verified double-pay path. The new history guard rejects it and the preview disables the button with the recovery message. Existing published-calendar overlap checks remain.
* **Record already processed:** `BatchFinalizer#record_manual_processing!` creates an immutable regular batch and one `committed / cornerstone_payroll_manual` batch event with the external run ID. It creates no entry payment-issued evidence and sends no outbox event. New behavior limits selection to the requested range, refuses out-of-range split lines, requires ascending work-date and cutoff order, and rejects payable source rows edited after the supplied snapshot. Overlapping regular batches or published calendars are rejected. Later unchanged rows subtract to zero; live arbitrary-range corrections are deltas. Calendar corrections need targeted cases. This action never reconstructs pre-edit hours from today's source row.
