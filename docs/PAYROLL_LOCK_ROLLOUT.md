# Installation payroll lock rollout

AIRE's payroll calendar belongs to the installation. Configure its cutoff activation once; it has no company foreign key.

After applying migrations `20261024080000` and `20261024090000`, and before enabling new calendar publication, run with the deployment's configured Rails environment:

```sh
bin/rails payroll:configure_lock_rollout STARTS_ON=2026-10-16 ACTOR='operator identity' REASON='Approved October manual and scheduled lock rollout'
```

The equivalent seed API is:

```ruby
PayrollLockRollout.configure!(
  starts_on: '2026-10-16',
  actor: 'Synthetic rollout acceptance',
  reason: 'Approved October rollout fixture'
)
```

The immutable singleton stores the boundary, operator identity, reason and timestamps. Configuration fails closed if **any** calendar before activation lacks explicit rollout evidence: manual `lock_mode` and a matching `cutoff_enforcement_starts_on`. This includes frozen legacy calendars. Stop deployment and obtain a reviewed resolution if the gate fails; do not rewrite history to pass it. No schedule, mode, publication revision or checksum is silently rewritten. Repeating configuration checks the same inventory before returning, so a legacy row that appears later also blocks an idempotent rerun. Standalone historical batches without a published calendar do not block configuration and remain unchanged. Creation also records `payroll_lock_rollout.configured` in the audit log, in the same transaction. The date must be the first or sixteenth of a month. Repeating the same date returns the existing configuration; changing it fails. Database triggers reject updates, deletion and truncation. This setting does not unlock frozen evidence.

New calendar publication fails closed without configuration. Send `lock_mode: 'manual' | 'scheduled'` and `cutoff_enforcement_starts_on: '2026-10-16'`; AIRE validates both against its own installation configuration. New preactivation manual publications must include **both** fields; omission fails even after nominal cutoff, preventing an old Payroll delivery worker from opening an unverifiable manual callback contract. Legacy scheduled callers on or after activation may still omit the fields; AIRE derives and freezes them from the installation boundary. October 1–15 is manual; October 16–31 and later are scheduled. Published mode and activation cannot drift, including through direct SQL updates. Request checksums retain existing replay compatibility; replays of retained publications do not rewrite their evidence. New values are also recorded in the publication revision and audit.

Manual calendars may first publish after their nominal cutoff. The nominal `cutoff_at`, date policy and existing cutoff trigger remain intact. The delegated cockpit Lock command requires the existing authenticated payroll-finalization capability, command ID, expected version and reason. It snapshots revision-ledger state at the database clock instant after obtaining the source ledger lock, including the frozen weekly overtime policy. Finalized rows, exclusions, settlement origin, audit and outbox are committed together. Repeating the command returns the same batch. The database also requires a persisted batch actor and an explicit manual-lock batch audit with the reason before a manual calendar can enter finalized state. This blocks an older scheduler from committing its nil-actor nominal-cutoff transaction during a mixed deployment. Scheduler calls and pending-cutoff claim fences skip manual calendars; a failed manual lock requires another explicit Lock action.

Finalized manual period JSON includes `locked_at`, equal to the frozen batch cutoff with six fractional digits. Its nominal `cutoff_at` remains unchanged. Manual batch payload `cutoff_at` and `generated_at`, export cutoff and finalization metadata, discovery and outbox timestamps preserve that same microsecond instant. Historical frozen payloads are never rewritten. Settlement reconciliation uses the frozen batch cutoff so work included between nominal cutoff and Lock is not mislabeled as late. Later paid-time claims still subtract frozen evidence.

Manual published-calendar Lock freezes approved negative corrections, including a category reclassification's negative reversal leg, just as scheduled calendar finalization does. The frozen payload sets `requires_negative_adjustment_review: true` whenever it contains a negative adjustment. Lock freezes source evidence; it does not authorize compensation changes. It never fabricates a negative-adjustment acknowledgement or uses the Lock reason as negative approval. Cornerstone Payroll import still requires explicit negative-adjustment acknowledgement and an explanatory note through its existing workflow. Standalone manual batch finalization outside published calendars retains its own acknowledgement-and-note requirement. Missing-category guards are unchanged.

A late manual Lock remains allowed after the next scheduled period freezes. New overnight segments belong only to their calendar dates; existing later frozen claims remain in the settlement target, so omission from an earlier range does not invent a reversal. Changed or deleted represented work still produces correction deltas and negative-review requirements. A delayed scheduled worker orders regular batches by work period rather than snapshot timestamp: an earlier manual period locked later is permitted, while a genuinely later finalized work period still blocks it. It keeps the original scheduled revision cutoff and subtracts all existing claims; a newer earlier-period snapshot is not reinterpreted by the older scheduled snapshot. Scheduled calendars retain due fences and retry behavior. `next_scheduled_cutoff_at` is installation-wide on the calendar index and every calendar response. It selects the earliest unfinalized enforced scheduled calendar, including a delayed due calendar. It is null when none exists.

Migration preserves every existing calendar's stored scheduled mode and all frozen batches, revisions, checksums and outbox payloads. After configuration, unfinalized legacy calendars before activation are excluded from automatic due selection, direct scheduler finalization, pending claim fences and next-cutoff discovery. They are not silently converted to new manual publications. Review any such row before rollout; the immutable cutoff trigger still applies. Already-finalized historical calendars remain readable and retain their frozen settlement protections. Unlinked historical manual-processing workflows remain available outside published calendar ranges.

## Coordinated deployment gate and staging rehearsal

The approved path assumes no legacy preactivation publication needs reconciliation. The owner has confirmed read-only production inventories of zero Payroll publications/periods and zero AIRE calendars; recheck at the actual deployment window. This is deployment evidence, not permission to rewrite any history.

1. Quiesce **old Payroll publication and delivery workers** before the AIRE-first window. Stop new publications, retries, and operator calendar changes; record exact worker/build identities and verify no in-flight delivery remains. Drain **all old AIRE cutoff/outbox workers** and record that they have stopped. Keep both flows quiesced through migration, configuration and paired version verification. The manual actor database guard does not replace drainage.
2. In staging, rehearse against synthetic data first: zero inventories permit configuration; a preactivation calendar missing rollout fields must refuse initial configuration whether unfinalized or frozen; it must also refuse the same-date rerun if such a row appears afterward. Verify refusal leaves configuration, calendar, batch, rows, checksum, revisions and outbox unchanged. A standalone August 1–15 batch without a calendar must remain unchanged and permit configuration. Do not remove legacy evidence just to make the gate pass.
3. Apply the new migrations with workers drained. Inventory **all** preactivation AIRE calendars, including frozen rows, and all retained preactivation Payroll publications, including pending/delivered retries. Stop if any lacks explicit rollout fields. Run each app's configure task and verify the same October 16 boundary. Run the task again to exercise the idempotent inventory gate. Record operator, reason, builds, inventory and receipts.
4. Attempt a new omitted-field October 1–15 publication: AIRE must reject it without a calendar/revision/outbox. Publish with explicit fields and verify manual mode. Publish October 16–31 and verify November 7 at 17:00 Guam. Rehearse both orders: scheduled freeze then November 8 manual Lock; November 8 manual Lock then delayed scheduled freeze. Verify same-week and overnight segments once, frozen claims, original scheduled cutoff, correction review and callback/import agreement through the paired UI.
5. Verify both applications and new workers are on the approved paired commits before resuming publication, delivery, cutoff and outbox processing. Retain a release hold on any failed inventory or acceptance gate. No complex legacy reconciliation or historical rewrite is part of this rollout.

No production data changes or remote deployment are part of this implementation. Parent owns paired connected UI acceptance and release approval.
